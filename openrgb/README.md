# OpenRGB 音乐灯效

把 EchoMusic 当前播放的音乐映射到 OpenRGB 灯光设备。独立于「频谱可视化」插件；可以同时使用，也可以只开灯效。

## 使用

1. 需要 EchoMusic `>=2.3.2-beta.4`，该版本开始提供本插件依赖的通用 TCP API（含 `AbortSignal` / `end`）。`2.3.2-beta.3` 发布版不支持。当前 beta.4 尚待发布，本地开发构建也需要使用对应版本号才能通过宿主兼容性检查。
2. 启动 OpenRGB，在 SDK Server 页开启服务。默认地址 `127.0.0.1:6742`。
3. 从插件源安装并启用「OpenRGB 音乐灯效」，打开其设置，点击「保存并连接」。首次安装默认不自动连接，也不选择任何设备。
4. 勾选需要控制的设备，播放音乐。未勾选设备不会收到灯效命令。不支持 Direct 逐灯模式的设备会显示原因且不可选择。

主机可填写本机、内网 IP 或主机名；IPv6 不加方括号。切换服务器会清空设备选择，避免接管另一个服务器上的设备。已启用连接的配置在下次激活时自动连接；「断开连接」同时关闭自动连接。

## 灯效

- **频谱铺展**：按 OpenRGB 的 LED 顺序，从低频到高频排列；不代表键盘或灯带的物理坐标布局。
- **整体音量律动**：使用音频 RMS 驱动全部灯珠的亮度。
- **低频节拍**：使用约 30–250 Hz 的频段能量。
- 配色支持极光、余烬、冰蓝；可调亮度、灵敏度、衰减平滑及 5–30 FPS。
- 默认暂停、停止播放或超过 750 ms 没有新音频帧时熄灯；也可选择保留最后颜色。
- 全设备控制，分区名称用于识别设备；第一版不提供分区单独选择、矩阵布局编辑或硬件模式编排。

## 生命周期与性能

只在主窗口插件运行时创建一份连接，不进入 Mini 或桌面歌词运行时。灯效由音频订阅与独立发送循环驱动，不依赖 DOM、窗口可见性或 requestAnimationFrame。主窗口隐藏/最小化仍可运行；窗口重载、停用、卸载或应用退出会停止发送并清理连接。

连接断开后按 1、2、4、8…秒退避重连，最长约 30 秒（附少量随机延时），重新协商协议并发现设备。设备列表变更通知会立即使旧编号失效，关闭连接后重新发现；按服务器、设备类型、名称、厂商、序列号、位置匹配之前的选择，不保存设备编号。无法区分的重复身份设备不会接管。

灯效与屏幕频谱共享宿主频谱服务；按实际频谱帧的频段范围和数量映射。无设备选中时不订阅音频。最多一个发送批次在途，发送等待期间只保留最新音频帧，不排队积压旧灯效；相同颜色不重复发送。

插件仅切换明确标识为 Direct、支持逐灯颜色且不带自动保存标志的模式，不回退到 Static/Custom，不写设备持久化配置。**取消勾选、断开连接、停用或退出后保留最后颜色和模式，不保证恢复原模式。** 如需恢复，请回到 OpenRGB 选择原灯效或配置文件。避免其他灯效软件同时控制相同设备。

## 协议与限制

使用 [OpenRGB SDK](https://openrgb.org/sdk.html) 的 TCP 二进制协议，协商最高版本 3，支持协议 1–3（OpenRGB 0.5 起，以及提供这些兼容协议的新版服务器）。不实现协议 0 的超时回退，也不使用新协议的专有功能。协议依据：[官方格式说明](https://github.com/CalcProgrammer1/OpenRGB/blob/master/Documentation/OpenRGBSDK.md)。

支持拆包/粘包、长度校验、设备列表变更、连接取消及请求超时。连接超时 4 秒，单次写入超时 2 秒，查询响应超时 3 秒。启用 TCP keepalive（首次探测延时 15 秒），它不能代替协议心跳或即时断线检测。

限制：单个协议包 1 MiB、最多 128 个设备、每设备 4096 LED、总共 32768 LED；超出时显示错误并停止该次连接。TCP 直接连接服务器，不经过 HTTP 代理，不提供 TLS。设备发现和硬件驱动由 OpenRGB 负责，插件不启动 OpenRGB 或扫描 USB。

## 开发与验证

`index.js` 为无外部依赖的单文件 ESM，无需打包；宿主通过 blob URL 加载。图标为 SVG。

在仓库根目录运行：

```sh
node --test tests/openrgb.test.mjs
```

测试覆盖二进制编解码、分片网络流、协议协商、超时、设备变更、设备身份、发送背压、频谱映射和停用清理。使用本地模拟 SDK Server 验证，不代替真实硬件兼容性测试。
