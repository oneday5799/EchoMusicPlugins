# 主题包维护脚本

这里的文件用于维护仓库中的主题插件，不是独立插件，也不在用户安装时执行。

| 文件                      | 用途                                                                                                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build-theme-plugins.mjs` | 读取仓库根目录下每个 `theme-*` 包的 `themes.json`，将共享运行代码和主题配置写入对应的 `index.js`。                                                    |
| `theme-kit/runtime.js`    | 共享主题运行代码的源文件，包含图片背景、视频背景和精灵动画，以及暂停、恢复和资源释放逻辑。生成时复制到各包的入口中，插件运行时不从 `scripts` 导入它。 |

## 修改与验证

在仓库根目录执行，无需安装额外依赖：

```sh
# 修改 themes.json 或共享运行代码后，重新生成两个包的入口
node scripts/build-theme-plugins.mjs

# 只检查已提交入口是否与配置、共享源文件一致，不写入文件
node scripts/build-theme-plugins.mjs --check

# 检查主题注册、素材完整性及动画生命周期
node --test tests/theme-plugins.test.mjs
```

不要直接修改 `theme-static/index.js` 或 `theme-dynamic/index.js` 的生成内容；下次生成会覆盖它们。单独替换素材内容而未改变文件名或配置时，不需要重新生成入口。

## 提交与安装

向此源码仓库提交主题插件时，一起提交 `scripts`、各包的 `themes.json` 和生成后的 `index.js`，并保留 Manifest、素材、README 与素材来源记录。生成入口也需要进入版本控制，EchoMusic 安装插件时不会运行构建脚本。

当前插件源索引分别指向 `theme-static/` 与 `theme-dynamic/`。宿主从仓库压缩包中定位对应插件目录并安装，根目录的 `scripts/` 和 `tests/` 不会装进插件目录。两个包各自包含完整入口与素材，可以独立安装，不需要把 `scripts` 复制进去，也不依赖另一主题包。

`app-theme-example` 是手写示例，不匹配 `theme-*` 目录名，不由本脚本生成。
